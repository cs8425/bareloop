        An id is a directory name: lowercase letters, digits and . _ - only. One is suggested when this dialog opens - change it freely, or clear it and a new one is made up when you press create.

        The model, MCP servers, system prompt and compaction parameters are inherited from the server configuration; change them per session in settings.

        session settings

        A tool may answer twice: once as text, and once as structuredContent — a JSON value the log keeps beside the text, never merged into it. This row says which of the two the model is sent; auto sends the JSON unless the text already carries the same bytes. On screen both channels are always shown, the second one folded shut inside its tool card. Whichever word you pick, the log is never rewritten — but the word is applied to every tool result the session already has, so changing it sends rewritten text for all of them on the next request and the server reads the whole history again instead of reusing its KV cache. Pick one and leave it. One server may use a different word than the session by adding a structuredContent key to its own entry in the list below. A JSON longer than show at most is sent as its beginning only, and the message then says how many bytes were left out — the model is told rather than left guessing. The log and this screen always keep all of it, so the number can be raised or lowered later: what changes is the next request, not what was stored. An empty box is no change rather than back to the default: write 16384 to put the default back on purpose.

        This browser asks this one, not the session: it says how much of your machine a growing reply may spend redrawing, so it is stored locally and never sent to the server. Text is never lost by redrawing less — the characters keep arriving and the next frame draws everything up to now. At 0 the bubble shows its cursor and the whole reply appears when the stream ends, which is cheaper than 1 Hz on a machine that cannot afford a parse a second; ?mode=plain is the readable version of that bargain (text as it arrives, markdown at the end). A ?hz= in the address bar wins over this row until the next load, and the streaming message prints the rate it is really managing in its own header.

        auto keeps choosing while the reply runs: it starts at 20 Hz and moves one rung at a time — 10, 5, 1, then 0 — down after three redraws in a row cost more than 60% of what the current rate promises, and back up after twenty cheap ones. It is judged on the whole redraw, follow-scroll included, which is the only way to catch the cost that lands after the markdown is drawn. What no rate can do is make a single redraw cheaper: on a long transcript the money goes to laying the document out again, so auto keeps the page from falling over rather than making it fast.

        Also this browser, not the session. On a touch screen there is no Shift+Enter a thumb can reach, so the default gives Enter back to the text: multi-line prompts and pasted code can be typed after all, and the round button beside the box sends. On a keyboard nothing changes: Enter sends, Enter during a live run interrupts that run and sends this instead, Shift+Enter is a newline. The on-screen return key and the box's hint text follow whichever answer you pick. ?enter=on|off|auto wins over this row until the next load.

        An empty API key keeps the stored one. Each session keeps its own log, MCP servers, system prompt, context window and compaction parameters. Saving while a run is active is refused; MCP servers reconnect only when their list actually changed. Turning image attachments off sends the model one line about the image instead of its bytes, which is what a text-only server wants.

        Prices are per 1 000 000 tokens and carry no currency: they are yours. All three or none — a half-entered price would mis-bill every request quietly. Leave them empty on a session that has no prices yet and nothing is billed; put 0 in all three to say a session is free. Changing a price changes the totals of everything already in the log, because what is billed is the usage each request already recorded, and it never reconnects anything.
